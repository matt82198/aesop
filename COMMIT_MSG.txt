fix(backup-fleet): prevent autodiscovery timeout by adding early heartbeat + per-repo bounds

Fixes the 22-minute watchdog hang reported in 20261029:

1. Write heartbeat at cycle START (before autodiscovery) so a hanging cycle
   still shows daemon alive to the monitor. Previous behavior wrote heartbeat
   only at cycle END, so a 22-min hang left the heartbeat stale for 22 min.

2. Wrap per-repo git operations (process_repo calls) in bounded timeout
   (default 60s, env-overridable). A single repo's hung git fetch no longer
   blocks the entire cycle.

3. Define REPO_OPERATION_TIMEOUT and AUTODISCOVERY_TIMEOUT constants
   (240s total so cycle fits in 5-minute schedule).

4. Log TIMEOUT status for repos that exceed per-repo timeout bounds,
   making slow repos visible in FLEET-BACKUP.log.

TDD: new test suite tests/test-backup-fleet-timeout-20261029.sh verifies
timeout logic and heartbeat at cycle start are present.

Measured facts (2026-10-29): 22-minute gap between heartbeat updates during
autodiscovery; next scheduled task (every 5 min) could not start due to
multiple-instance lock policy, leaving fleet unmonitored.
