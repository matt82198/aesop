# tools/ — Build utilities
Local-only Python (stdlib only, no external deps), bash (POSIX, CRLF-safe).
## Universal rules (every domain)
- Feature branch only, never main; every push gated by `python tools/secret_scan.py --staged` exit 0. Tests never pollute cwd or global git config; temp dirs only; dummy secrets are runtime-concatenated, never literal.
- In worktrees use ABSOLUTE paths under the worktree for every write; redaction and path-handling code must genericize over Windows profile names (use `[A-Za-z0-9_]+` regex, not hardcoded) so checkout works across shared boxes.
- Domain docs stay minimal-but-complete; update this file in the same PR as code it describes.

## Core invariants
- **Never print secrets**: mask as pattern name + masked value only; NEVER output raw credentials/tokens. **AESOP_STATE_ROOT**: all heartbeat/ledger/logs use `AESOP_STATE_ROOT` env var (default `./state`) or CLI args; no hardcoded personal paths.
- **halt.py state-dir default**: `resolve_state_dir()`'s precedence is `AESOP_STATE_ROOT` env > `aesop.config.json` `state_root` > `$AESOP_ROOT/state` (when `AESOP_ROOT` is set) > `common.get_state_dir()`'s cwd-relative `./state`. The `$AESOP_ROOT/state` step (fixed 2026-10-05, PR #773) matters because callers that `cd` elsewhere before invoking `halt.py --status` (e.g. `daemons/run-watchdog.sh`'s single-source-of-truth delegation) must still find a sentinel written at `$AESOP_ROOT/state/.HALT` — a bare cwd fallback silently missed it and let a halted daemon keep running.
- **status.js heartbeat path resolution (2026-10-29)**: resolves heartbeat paths with conductor3 preference (env override, then conductor3 location, then local fallback) to match ui/config.py; tests: `tests/status-cli-heartbeat-paths.test.mjs`.
- **Fragment-assembled secrets in tests**: `scanner_selftest.py` concatenates dummy secrets at runtime so pattern text never appears contiguously (self-scan invariant).
- **verify_*.py are mandatory CI gates**: `verify_dash.py`, `verify_submit_encoding.py`, `verify_activity_filter.py`, `verify_agent_inspector.py`, `verify_prboard.py`, `verify_failure_drilldown.py`, `verify_wave_telemetry.py`, `verify_dispatch_panel.py`, `verify_scorecards.py`, `verify_ui_trio.py`, `verify_cost_panel.py`, `verify_cost_summary_drawer.py`, `verify_receipt.py`, etc. are required pre-push gates; use `--allow-skip` only in truly browserless environments (CI must run all).
- **lock.mjs is the ONLY lock implementation**: never reimplement locking in `proposals.mjs` or elsewhere; all proposals/state updates must use fail-closed `lock.mjs` with exponential backoff + stale-lock breaking. The backoff sleeps via `Atomics.wait` (synchronous, yields the core; `acquireLock` must stay sync), never a busy-wait (tracker 4fc897d6b12f; tests: `tests/lock.test.mjs` "sleeps during backoff").
- **Loop-Proof gate (2026-10-20)**: `loop_proof_check.py --base <rev> [--head <rev>]` refuses a range that changes a file listed in `LOOP-MANIFEST.json` (daemons/run-watchdog.sh, daemons/selfheal.sh, daemons/backup-fleet.sh, and this tool) unless a commit carries `Loop-Proof: <declared test> red=a/b green=c/c` (red before, fully green after). Fail closed: exit 1 = unproved or refused, exit 2 = manifest unreadable at head. A manifest introduced in the range protects its listed files from that commit on. Wired as a PR-only CI step in ci.yml (shard 0). Trailer counts are shape-checked, not re-executed. Tests: tests/test_loop_proof.py, tests/test_loop_manifest_integrity.py.
- **Conflict marker gate (Guardrail G14, 2026-10-06)**: `conflict_marker_check.py` scans tracked text files for literal unresolved markers (`<<<<<<<`/`=======`/`>>>>>>>`/diff3 `|||||||`) via `--check` (full tree; wired as a CI gate, ci.yml shard-0) or `--staged RANGE` (added-lines-only diff, pre-push hook); skips binaries + `tools/.conflict-marker-allowlist.json` paths, honors inline `# conflict-marker-ok`; exit 0=clean/1=findings/2=error; an unreadable tracked file (AV lock, permission denied) is exit 2 with the path named in BOTH `--check` and `--files` modes, never a skip. Closes the PR #834 gap: merge commit b2c4db77 landed a literal `<<<<<<< HEAD` block in this very file and claudemd_lint/claudemd_sync_gate/all PR CI passed because none of them scan for conflict markers.
- **power_selftest.py scanner check fails closed (2026-10-05)**: a check that cannot locate/run/parse `scanner_selftest.py` renders `scanner:FAIL`, never `scanner:None`/`n/a`/OK -- a silently-broken scanner gate must never read healthy. Every check result funnels through `render_segment()`, which treats a `None` result or an OK/WARN `DETAILED_OK_CHECKS` (`decisions`/`scanner`/`trigger`) result whose `details` is `None` as `FAIL:unevaluated`. Tests asserting the overall exit code (e.g. `TestPowerSelftestHookDetection`) must pin `SCRIPTS_ROOT` at a real `scanner_selftest.py` so the scanner check is deterministic regardless of whether the CI runner's `$HOME` happens to carry `~/scripts` -- otherwise an unrelated check flips the exit code these tests assert on.

## init_project.py — Worktree support
- **Worktree .git handling**: `resolve_real_git_dir()` detects when `.git` is a FILE (worktree case) and uses `git rev-parse --git-common-dir` to locate the actual git directory.
- **Fallback git dir resolution**: Manual parsing of `.git` file's `gitdir:` pointer if git command fails. Every branch returns `Path(...).resolve()` (8.3 TEMP alias `RUNNER~1` / subst drives differ from raw paths).
- **Hook installation**: `install_pre_push_hook()` uses resolved git dir to place hooks in the common directory (not worktree), preventing ENOTDIR errors in worktree scenarios. Hooks dir is resolved by `common.resolve_hooks_dir` (git `--git-path hooks`, honours worktrees + core.hooksPath); health_score FAILs on git error (tests: `tests/test_health_score.py::TestHealthScoreHooksDirResolution`).
- **Pre-push hook template (`PRE_PUSH_HOOK`)**: reads the pre-push stdin lines and runs `secret_scan.py --range` over each pushed `remote_sha..local_sha` (new branch: merge-base with the default branch, else the empty tree), in addition to `--staged`; fail-closed on findings, scanner error, missing scanner or malformed input. Written as LF bytes (`install_pre_push_hook`). Tests: `tests/test_init_project.py::TestPrePushHookScansPushedRange`.
- **Security**: symlink checks preserved throughout resolution. `install_pre_push_hook` refuses a symlinked `.git/hooks/pre-push` even under `--force` (the check runs before the exists/force decision, so `write_bytes` never follows the link). Tests: `TestInstallPrePushHook` in `tests/test_init_project.py`.
- **Pre-push hook scans pushed refs**: the hook `init_project.py` installs reads git's per-ref stdin, blocks pushes to `refs/heads/main|master`, and runs `secret_scan.py --range <remote-tip>..<local-tip>` per ref (whole tree for a new ref); `copy_secret_scan_script(force=)` refreshes a stale scan script only under `--force`. Tests: `tests/test_init_project.py`.
- **state/ git-ignore (F-10, 2026-10-14)**: `ensure_state_gitignore()` appends a marker-delimited block (`state/*` + `!state/.gitkeep`) to the scaffolded `.gitignore`, idempotent on re-init. Without it `git add -A` staged the SQLite event store and tracker json. Tests: `tests/test_init_gitignore.py`.
- **Push-gate artifacts (0.10.1)**: `generate_push_gate_artifacts()` runs the five generators `doctor` requires (`tools/INDEX.md`, `.pyflakes-baseline.json`, `.subprocess-guard-baseline.json`, `.portability-baseline.json`, `.stateapi-baseline.json`) from this tools dir with cwd set to the target repo, in parallel, after the hook install. Existing artifacts are kept unless `--force`; `AESOP_SKIP_PUSH_GATE_ARTIFACTS=1` skips. `DEFAULT_CONFIG` writes `"repos": []`. Tests: `TestInitWritesPushGateArtifacts` in `tests/test_init_project.py`.
- **Doctor port check (2026-10-17)**: `doctor.js` `resolveDashboardPort()` probes the port `aesop dash` launches on (`PORT` env, then `aesop.config.json` `dashboard.port` via `ci_config.loadAesopConfig`, then 8770); the row is labelled `Port N available`. Tests: `tests/doctor-dashboard-port.test.mjs`.

## Key tools
- **tools/event_store/init.py (G1.1 L2, 2026-10-22)**: creates a per-project event store: orphan branch + worktree, `store.json` `{"project","schema":2}`, `*.jsonl -text` attributes, empty events/ and runs/, and the append-only guard `tools/event_store/guard/events_append_only.sh` (ported from conductor3 unchanged). - **tools/rotate_logs.py (copy-truncate, 2026-10-16)**: archive is created exclusively (`xb`) from the bytes read under the sidecar lock, then the kept half is rewritten into the live log in place and truncated (same inode, so `>>` handles held across a rotation keep writing). os.replace was rejected: a rename orphans long-lived writers and fails with rc=1 on Windows while another process holds the file. Known window: an append between the final size check and the truncate is lost. Callers: `monitor/collect-signals.mjs` (execFileSync); shell daemons write with per-write `>>` and long-lived child `>>` (`daemons/run-watchdog.sh` pr_sweep and git_integrity_check). Tests: `tests/test_rotate_logs.py`.
- **tools/gen_tool_index.py**: Generated INDEX.md builder. Updated 2026-10-07: --check mode uses `git hash-object --path` for EOL-agnostic comparison; generated content hash vs working-tree file hash both normalized through git's .gitattributes/core.eol rules. Fixes Windows false positives where CRLF/LF byte differences were misreported as stale. --regenerate writes LF-only (standard git storage format). Post-#925 fix (2026-10-07): when passing expected content to git hash-object via stdin, use binary encoding to avoid Python's platform-specific line-ending conversion on Windows (text=True was converting LF to CRLF). The check_via_git_hash() function now encodes strings as UTF-8 bytes before passing to subprocess, then decodes the hash output.
- **tools/git_integrity_check.py (fail-closed --repos-json, 2026-10-20, tracker 5999373469c2)**: an explicit `--repos-json` is authoritative. A missing, unreadable or malformed file, a non-list payload, or an empty list exits 2 with a specific error; stdin is read only when `--repos-json` is absent. Previously a parse error fell through to a stdin read with no timeout, which could block the watchdog cycle. Tests: `tests/test_git_integrity_check.py` (`test_malformed_repos_json_fails_closed_without_reading_stdin`, `test_empty_repos_json_does_not_read_stdin`).
- **tools/goal_state.py + tools/boot_state.py (2026-10-15)**: `goal_state.py set|show|history` appends/prints the orchestrator GOAL as `goal_set` events on stream `orchestrator_goal` (StateAPI append, never patched); `boot_state.py` prints the ONE canonical boot brief (GOAL, STATE.md `## ACTIVE`, BUILDLOG tail, event-store projections, git) capped at `--max-bytes` (default 12000), exit 2 with no stdout when the store is unreadable or missing.
- **tools/regen_all.py**: Regenerator runner. Updated 2026-10-07: paths_with_real_diff() returns all modified paths for restoration in --check mode, preserving fixture byte-identity.
