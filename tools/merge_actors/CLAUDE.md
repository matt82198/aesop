# tools/merge_actors — merge train, halt, worktree markers and PR sweep
Merge-actor tools: the halt kill switch, the merge train and merge queue, worktree ownership markers, and the PR sweep.
- **Halt kill-switch enforcement**: `merge_train.py` gates ALL entry points and merge actions with `halt.py` checks; halted tool exits 1, import failure exits 2 (FAIL CLOSED). `halt.py` provides the public API: `is_halted()` / `get_halt_info()` / `clear_halt()` / `resolve_state_dir()` (respects `AESOP_STATE_ROOT` env > config `state_root` > default). Sentinel location: `<state_dir>/.HALT` (JSON). Box-wide: `halt.py set` also writes `$CONDUCTOR_ROOT/state/.HALT` (resolved by the daemons/conductor-root.sh rule: explicit `CONDUCTOR_ROOT`, else the sibling `conductor3` only for the canonical `aesop` AESOP_ROOT, else UNRESOLVED and fail closed with exit 3; no home fleet-root fallback) and `--status`/`--clear` honor it, unless `AESOP_STATE_ROOT` is set (isolated override). Do not edit the sentinel manually; use `halt.py set/--clear` CLI.
  - **Merge actors read both sentinels (2026-10-15, F1):** `merge_train.halt_status()` (mirrored as `merge_queue._halt_status()`) consults `active_halt()` (box-wide, then checkout) and treats any reader error as HALTED; a box-wide halt stops merges even when the checkout has no `.HALT`.
  - **PR head refs are fork-controlled (F2):** `merge_train.head_ref_problem()` refuses option-shaped, empty, `@{` and check-ref-format-invalid names before any git call, and every fetch passes `--` before the refspec. Tests: `tests/test_merge_actors_box_halt_and_ref.py`.
- **Merge-queue daemon (merge_queue.py) self-heals on crash**: when a pass crashes mid-batch and leaves the shared worktree checked out on an `integrate/q-*` branch, the next pass detects this in `worktree_is_safe()` and automatically reparks to main before proceeding. No manual intervention needed; stalled passes recover transparently.
- **Queue root isolation guard (2026-10-06 incident)**: `build_batch()` refuses to mint `integrate/q-*` branches unless `AESOP_QUEUE_ROOT` env is set and matches the current working directory (resolved paths account for symlinks/case on Windows). The `git()` helper in `merge_train.py` accepts an optional `cwd` parameter (default None preserves backwards compatibility) to allow tree-mutating calls to explicitly target the queue root. This prevents accidental branch creation in lane worktrees: lanes calling build_batch() from sibling worktrees created real `integrate/batch-*` branches because git() had no cwd. Daemon: `daemons/run-merge-queue.sh` exports `AESOP_QUEUE_ROOT` before cd'ing and invoking merge_queue.py.
- **Worktree ownership guard (2026-10-14 incident)**: `worktree_marker.py` writes/reads `.aesop-worktree-owner` (`{"owner","mode": rw|ro}`) at a worktree root (`write --root D --owner ID --mode rw|ro`, `read --root D`); an unreadable or malformed marker fails closed.
  - `merge_train.create_integration_branch(batch, cwd=, owner=)` runs `git worktree add -b integrate/*` (throwaway temp-dir worktree, never a checkout in cwd) only inside a `cwd` that is the `AESOP_QUEUE_ROOT` or carries an rw marker owned by `owner` (CLI `--cwd`/`--owner`, default owner `AESOP_WORKTREE_OWNER`); anything else is refused with the resolved path named (ASCII-only).
  - **Origin gate (2026-10-15 incident, a read-only lane leaked `integrate/batch-20261014-2157` to origin and failed CI's remote-refs tripwire):** every origin write from merge_train (integrate/* push, PR create, remote delete) needs `--push-origin` AND `AESOP_QUEUE_ROOT` naming a valid repo (`origin_push_authorised`, mirrors merge_queue.build_batch); otherwise the run is local-only, prints `DRY: would push <branch>`, exits 0. After a push, a finally block deletes origin/<branch> only if it still points at the pushed sha. Tests: `tests/test_worktree_ownership_guard.py`, `tests/test_merge_train.py` (`TestIntegrationOriginGuard`).
- **tools/merge_queue.py**: Merge-queue advancer. Updated 2026-10-06: added AESOP_QUEUE_ROOT isolation guard (refuses to mint integrate/q-* branches unless running in dedicated queue checkout). Updated 2026-10-15: the `.merge-queue-lock` directory is reclaimed by holder pid, not age alone. A live holder (`_pid_alive`, never signals on Windows) is never reclaimed; a dead holder is reclaimable at any age; age past the 600s bound is the only path when no pid is recorded. Tests: `tests/test_merge_queue_lock_liveness.py`.
- **tools/merge_train.py**: Transport layer. Updated 2026-10-06: git() helper now accepts optional cwd parameter for explicit working directory control. Updated 2026-10-15: `halt_status()` reads box-wide and checkout sentinels fail-closed; `head_ref_problem()` gates fork-controlled headRefName; fetches pass `--`. Updated 2026-10-20 (tracker 31c0ddd1e22b): every merge is pinned with `--match-head-commit` to the head sha that was read green (`pr_state().head_oid`; the integration merge pins to `pushed_sha`); an empty pin refuses the merge with no `gh` call. Tests: `TestMergePinsSnapshotHead` in `tests/test_merge_train.py`.
- **tools/auto_merge.py scoped verdict (F-03, 2026-10-14)**: `auto_merge.py <n>...` exits 0 only if every named PR is `gh pr view --json state,mergedAt` MERGED; nonexistent or closed-unmerged PRs exit 1 and are named on stderr. Tests: `tests/test_auto_merge_scoped_verdict.py`.
- **tools/auto_merge.py fix path is caller-safe (2026-10-16)**: `fix_branch()` works in a detached temp worktree removed on exit, so the caller's HEAD and untracked WIP are never checked out, pulled or staged; only tracked paths the fix rewrote are staged (never `add -A`). Before push, `secret_scan.py --range origin/<branch>..HEAD` scans the committed fix delta, and a non-empty delta reported as 0 files inspected fails closed. Tests: `tests/test_auto_merge_shell.py` (`TestFixBranchLeavesCallerCheckoutAlone`, `TestFixBranchSecretGate`).
- **tools/auto_merge.py honours the box-wide halt (2026-10-15)**: `halt_reason()` consults `halt.active_halt()` (box-wide `.HALT` then checkout `.HALT`) and fails closed on import or reader error; a halted box exits 1 before any GitHub call, and the check is re-run before every `merge_pr` and `fix_branch` (origin write). Mirrors `merge_train`/`merge_queue`. Tests: `HaltGateTests` in `tests/test_auto_merge_scoped_verdict.py`.
- **CI-gated merge helper (`ci_merge_wait.py`)**: after any `gh pr merge` timeout or failure it reads PR state once (`gh pr view --json state`); MERGED exits 0 (the merge landed), OPEN after a timeout retries, unreadable state after a timeout exits 1 without retrying (fail closed). Tests (`tests/test_ci_merge_wait.py`) drive `main()` with a scripted fake `gh`, never a real PR.
- **pr_sweep.py (STATE.md item 9 residual, PR #871 gap)**: the session-independent PR actor -- arms missing native auto-merge ONLY when `baseRefName` is the repo default branch (a stacked PR is reported `STACKED ... stacked on #N; retarget to <default> after #N merges`, never armed; default-branch read failure exits 3 with nothing acted on), reports BEHIND branches (capped at 2/run, oldest first, 20-min throttle; never server-updated, the lane merges main locally), and signals stuck-red (required check failing, head >30 min old) / DIRTY PRs as `pr.red`/`pr.dirty` rows to `<conductor_root>/state/signal-hub-queue.jsonl` (`common.get_conductor_root()`, never a hardcoded path), deduped on `(pr, head, type)`. Never rebases/pushes/merges.
  - Zero-check retrigger (PR #932/#934 class): armed PR with empty `statusCheckRollup` and a head >=20 min old gets `gh workflow run ci.yml --ref <head>` + a `sha=` marker comment (a DIRTY/CONFLICTING PR with zero runs instead gets `needs-rebase` + a sha-keyed conflict comment: no dispatch, auto-merge left armed, never disarmed); still zero 24 h later (non-conflicted) it is disarmed (`--disable-auto`) and labelled `needs-ci-trigger`.
  - Reads fail closed (exit 3, nothing acted on; this includes `gh pr checks --required` errors, which are no longer read as "no required checks" unless gh says so; the PR listing is `--limit PR_LIST_LIMIT` = 1000, and a listing that reaches the cap exits 2 instead of sweeping a partial set; tracker 5f0c5b842f2b). Per-PR write failures are isolated (logged with PR + reason, counted, loop continues to the next PR, exit 1 at the end); actions log to `<conductor_root>/state/pr-sweep.log`.
  - Invoked on a 15-min throttle from the watchdog daemon so the nudge does not depend on a live orchestrator session noticing via the Monitor tool.
  - `gh()` passes `stdin=subprocess.DEVNULL`: the watchdog runs hidden (`daemons/run-hidden.exe`, CREATE_NO_WINDOW) where the inherited STD_INPUT_HANDLE is invalid, so `subprocess.run` raised `OSError [WinError 6]` before gh started and aborted every cycle from 2026-10-17 (regression of the 2026-10-16 hidden-launcher change). Tests: `tests/test_pr_sweep_stdin.py`.
