# tools/gate_wiring — adding, indexing and wiring gates

Gate-wiring rules for `tools/`: the tool index, the checklist for adding a pre-push gate, and the generated-artifact merge triangle.

## Tool index

- Full one-liner index of every tool in this directory: see `tools/INDEX.md` (generated by `tools/gen_tool_index.py --regenerate` from each file's own `INDEX:` header line; never hand-edit it -- the byte-identity gate rejects drift). This file stays navigation only so a tool-adding PR never conflicts with every other in-flight PR over the same inline list (that conflict-magnet is why PR #751 moved the index out of here). Index merges through the `aesop-regen` driver (`.gitattributes` -> `generated_merge.py`, registered per clone by `install_merge_drivers.py`; the pre-push hook does that for you): a structured 3-way merge of entries rendered through the generator, so two PRs each adding a tool merge to an already-regenerated index.
  - (git's `union` kept both sides verbatim and left the index unsorted/duplicated on every merge-from-main: #784/#856/#739.) Rule: merge-from-main = merge, then `python tools/gen_tool_index.py --regenerate && git add tools/INDEX.md`, or let the driver/gate do it — `generated_push_gate.py` (hook `check_generated_regen()`) verifies the COMMITTED bytes of every registered regenerable artifact (`generated_paths.REGISTRY` entries with a `regen` argv; must equal `merge_queue.REGENERATORS`) at the pushed tip in a throwaway worktree and rejects a stale one with exactly that instruction; the driver's per-worktree `.needs-regen` stamp (`git rev-parse --git-path aesop-needs-regen`) forces the check even on an empty range.

## Adding a new gate (2026-10-06, PR #872 postmortem)

- Adding or wiring a pre-push gate took PR #872 five red CI rounds -- a different checklist item each time. Two fixes: `gate_stub_list.py` derives `tests/test_pre_push_policy.sh`'s TTY-fixture stub list from the real `check_*` functions in `hooks/pre-push-policy.sh` (parses for `gate_tool_status()` call sites) instead of a hand list a new gate is never automatically added to -- see `tests/test_gate_stub_list.py` for the red-first proof a dummy `check_zzz` is picked up. It also matches `gate_tool_status "$gate_dir"` (base-copy gates such as `check_symbol_survival`).
  - `new_gate_check.py` runs the whole checklist in one command (pre-push self-test, `gate_inventory.py` axis2 parity, `claudemd_lint.py` working-tree + `--headroom` (line counts match `wc -l`, `_wc_line_count`), `claudemd_sync_gate.py`, `portability_check.py` ratchet, `verify_gates_wired.py` (also reads every nested tools/**/CLAUDE.md), `dispatch_lint.py`, `conflict_marker_check.py`, and a dry pre-push range check against `origin/main` with no real push) and prints the exact fix command for any red row; exit 0=all green/1=any red/2=usage error. Allowlisted in `tools/gate-inventory-allowlist.json` (operator-invoked meta-tool, no file-content rule of its own to wire into CI).
  - The `--baseline FILE --json` protocol that `baseline_liveness_check.py` calls runs ONLY the `portability_check.py` ratchet (one scan, ~1 s; the full checklist took 69 s against a 120 s timeout on 2026-10-15) and reports its real stale/new lists; tests `BaselineLivenessQueryTests` in `tests/test_new_gate_check.py`. See `LANE-CONTRACT.md` section 5.

- Merge-carried copies (2026-10-14): `generated_paths.py --check` counts a registered path as touched only when HEAD's blob differs from both the merge-base blob and origin/main's (`is_touched_by_push`); unresolvable refs fail closed. A touched path is still allowed when HEAD's raw blob equals its generator's output (`regen_matches_head`, generator run in a throwaway `core.eol=lf` worktree); any failure to run or compare blocks.

- The dry-range row (2026-10-06 follow-up): a branch that merged `origin/main` legitimately carries changes to registered generated paths (`generated_paths.py` `REGISTRY`, e.g. `tools/INDEX.md`) whose regeneration is the hook's designed writer path (`AESOP_ALLOW_GENERATED=1`) -- running the real hook without that var set made this row false-red (9/10 on a clean branch, PR #882). The row now pre-checks changed registered paths against their generator's own `--check` (`GENERATED_FRESHNESS_CHECKS` in `new_gate_check.py`); fresh -> PASS with the escape hatch set for the dry run; stale -> FAIL with the exact regen command, never reaching the hook.

## Recent additions (2026-10)

- `generated_merge.py` / `generated_push_gate.py` / `install_merge_drivers.py` — the generated-artifact merge triangle (see § Tool index): regenerating merge driver, committed- bytes pre-push gate, idempotent per-clone driver registration. The gate runs each registered generator against the pushed tip in a detached throwaway worktree and compares through `git diff --quiet` (which applies core.autocrlf and .gitattributes line-ending normalization), so the gate correctly handles CRLF/LF differences on Windows without false positives. Fails closed on any mismatch of a path the push touched (or whose generator it touched); a path carried unchanged from the merge-base with origin/main is inherited (D46, 2026-10-16: regeneration belongs to main; see the hooks domain, item 15), so the gate no longer refuses branches for trunk's own staleness.
  - Generator trust: `--base-dir DIR` (the hook passes the trunk `tools/` copy) makes every generator run from DIR, never the pushed tree, so an edit to `gen_*.py`/`generated_*.py` cannot bless its own output; without it, a generator changed by the push (vs. the range base or origin/main) is reported stale and not run. Tests: `tests/test_generated_merge.py` (git integration incl. the `union` negative control, 3-way entry semantics, stamp, registry/queue agreement), `tests/test_generated_push_gate.py` (stale-commit rejection with the one-line instruction, dirty-tree-does-not-rescue, stamp consumption, sourced-hook wiring, autocrlf false-positive tests).
