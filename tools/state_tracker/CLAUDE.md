# tools/state_tracker — state store, tracker and checkpoint tools
State store, tracker and checkpoint tool invariants for the scripts under `tools/` that read or write `tracker.json`, the event stores, the task-event ingest and the boot brief.
- **state_rebuild.py --check is the tracker.json drift gate, not a proxy**: it diffs disk against the canonical materializer, so any tracker writer (e.g. `tracker_guard.py`) must close items through the sanctioned write facade — direct `tracker.json` patches are correct only until the next unrelated write re-renders the whole file from the event log (GAP, 2026-10-05).
- **tracker_guard.py --adopt-disk-items (2026-10-16)**: the only sanctioned way to adopt tracker items that exist in `tracker.json` but have no `item_created` event (the disk-only `cmc-err-*` family that makes every render fail the OCC guard). `--reason` is required for a live adopt, `--ids` must cover every disk-only item (partial adoption is refused), `--dry-run` plans and verifies without writing; it delegates to `WriteAPI.tracker_adopt_disk_items` (events are append-only, so reversal is a revert PR). Exit 0 on success, 2 on any refusal. Tests: `tests/test_tracker_adopt.py`.
- **tracker_guard.py fails closed on malformed data (df1f7058c269)**: a malformed or unreadable `tracker.json` (or a non-list `items`), or any corrupt journal line, raises `GuardDataError` and exits 1 in every mode; only an absent `tracker.json` is a clean no-op (exit 0). Tests: `tests/test_tracker_guard.py::TestTrackerGuardFailClosed`.
- **tracker_guard.py --enforce exits 1 on a failed revert (84e4a43f4140)**: a zombie whose WriteAPI revert raises is still a live violation, so `--enforce` reports it and exits 1 after printing the reverts that succeeded (it used to exit 0 and let the caller believe it healed). Test: `tests/test_tracker_guard.py::TestEnforceFailsClosedOnRevertError`.
- **state_rebuild.py --all/--check (F-02, 2026-10-14)**: `--all` no longer clobbers a stored STATE.md (it renders the newest `state_markdown` body verbatim); `--check` masks ISO timestamps only for the generated fallback. CI job `state-drift-gate` runs `--all` then `--check` fail-closed. DB paths resolve via `state_store/paths.py::resolve_db_path` (tracker vs instances roles; gen_state_md and instance_manager use it too).
- **tools/event_store/migrate.py (G1.1, L3)**: one-time split of the frozen v1 `events/log` into per-project v2 stores per docs/plans/PER-PROJECT-EVENT-STORES.md 4.2 (rule ids goal, repo, refkey, text1, multi, default). Refuses an unfrozen source, a broken chain or a non-empty target (exit 1, nothing written); `--dry-run` prints counts only; the manifest goes to `<source>/migration-manifest.json` on a real run. Its v2 writer is a stopgap that L1's store.py replaces in wave B. Tests: tests/test_event_store_migrate.py.
- **health-score.js python resolver (397553876e57)**: `tools/health-score.js` resolves the interpreter `python3` then `python` (same order as `health.js`/`dash.js`) and exits 1 with an explicit error if neither exists. Test: `tests/health-score-python-fallback.test.mjs`.
- **state_root migration (2026-10-17, PR #1090, decision b)**: `tools/state_root.py` is the STRICT resolver (fail closed). `common.get_state_dir()` is LEGACY with a cwd fallback and is unchanged. Callers migrate one at a time, only after the primary `aesop.config.json` `state_root` is absolute and fleet processes export `AESOP_STATE_ROOT`. Migration surface: the caller set listed in `tools/state_root.py`'s docstring.
- **tracker_reconcile.py --fix (70334b87760f, P0 wrong data)**: `FIXED` prints and exit 0 only when the StateAPI close write succeeded. A failed write prints `CLOSE-FAILED <id>` (still open), `--json` reports `fixed=false` with `closed=false` on the entry, exit 2. Tests: `tests/test_tracker_reconcile.py` (`test_fix_close_failure_*`).
- **tracker_reconcile.py / tracker_autoclose.py active statuses (a879cf665047)**: both allowlists treat `todo` and `in-progress` as active alongside `in_progress`, so a merged item in those statuses is reported as a zombie or SHIPPED. Tests: `tests/test_tracker_reconcile.py` and `tests/test_tracker_autoclose.py` (`*todo_and_in_progress*`).
- **Per-project event store core (`event_store/`, G1.1)**: stdlib-only package run as `python -I tools/event_store/cli.py append|verify`.
  - `store.py` `Store(path)` reads `store.json` (`{"project","schema"}`), appends schema-v2 lines (store-wide `seq`, `prev` = sha256 of the previous line across day files) and `verify()`s v2 global chains or v1 per-day chains; `store.json` also carries `head` (sha256 of the last appended line, written atomically on append) and verify reports one problem when the last line's sha differs, so a last-line edit fails verify (stores without `head` verify as before; v1 stores untouched).
  - `registry.py` reads `~/.claude/event-stores.json` (env `EVENT_STORES_REGISTRY` overrides) and maps `G<n>[.x]` to a project.
  - `cli.py append` refuses (exit 2) with no `--project` and no `--ref goal=`, a store/project mismatch, repo-encoded ref keys like `keyrun_pr_606`, and a ruling without `--ref goal=`, and commits (never pushes) in a git store.
  - A dir with day files and no `store.json` opens read-only as v1 (f-b15b603b; appends refused).
  - Tests: `tests/test_event_store_core.py`. The `project` subcommand renders pending, rulings by goal and checkpoints across per-project stores (tools/event_store/project.py; tests tests/test_event_store_project.py).
- **ingest_task_events.py torn-line recovery**: a malformed line with bytes after it (a torn record glued to the next) is quarantined to `<task-events.jsonl>.quarantine.jsonl` with its offset, error and raw text, and the cursor advances (exit 0, `quarantined=N`); a malformed newline-terminated LAST line is held (exit 3) until newer data arrives, and an unterminated tail is held. Recovery needs no action; replay a quarantined raw line by hand if its record matters.
- **ingest_task_events.py `--status` and `--max-bytes` (2026-10-15)**: `--status` is read-only and prints one `INGEST:` line (cursor, source_bytes, lag_bytes, heartbeat_age_s); it exits 1 with the word STALE when the `.task-ingest-heartbeat` is older than 900 s or missing, lag exceeds 256 KiB, or the cursor is past EOF (a missing source is NO-SOURCE, exit 0). `--max-bytes N` bounds one run; repeated runs catch up. The INGEST line and the status dict also carry `quarantined=N`, the total records in the quarantine file, so schema-invalid records dropped on ingest (e.g. missing `agent_id`) are visible; freshness is not changed by it. Tests: `tests/test_ingest_status.py`.
- **ingest_task_events.py agent lifecycle (2026-10-15)**: each agent-kind task event also appends one event to stream `agent_lifecycle` (`agent_done`, or `agent_stalled` when `stop_reason` contains "error" or is `max_tokens`/`refusal`), deduped on a key derived from the task event_id so re-runs add no rows. Folded by `project_agent_lifecycle`. Tests: `tests/test_ingest_task_events.py`.
- **boot_state.py INGEST line (2026-10-15)**: the EVENT STORE section starts with an `INGEST:` line. Before projecting, an existing store gets one bounded ingest run (`run_ingest`: 5 s timeout, 4 MiB cap, `--jsonl` optional). The line carries the freshness numbers plus `| ingest run: ok|failed exit N|timed out after Ns`, and says STALE when the ingest could not run, failed, timed out, or the heartbeat is stale (a non-ok run never reads fresh, even inside the heartbeat window), so a reprime never silently serves a stale projection. GOAL is bounded to a quarter of the cap with a `[GOAL truncated N bytes]` marker; every section keeps its heading. Exit stays 0 (the STALE line is printed). The brief never ingests into an absent store. The clock-dependent heartbeat age is the one documented exception to byte-identical output. Tests: `tests/test_boot_state.py` (INGEST cases).
