# tools/ci_isolation — CI capability, runners and test isolation
CI capability, runner, workflow-lint and test-isolation rules for the tools/ domain.
- **Workflow validity (GAP 2026-10-06)**: `ci_workflow_lint.py` checks GitHub schema SEMANTICS, not just YAML — `strategy` keys, `matrix.<k>`/`exclude` resolution, `needs:` targets, `runs-on` form, and per-key context availability (`shell:` allows none) — and runs actionlint when found (`$ACTIONLINT_BIN`/PATH; `CI_WORKFLOW_LINT_REQUIRE_ACTIONLINT=1` fails closed, ci.yml sets it). A PyYAML-valid main-full.yml with `exclude:` beside `matrix:` ran ZERO jobs for ~10 merges while this gate was green. Escape signature for the detector: run `conclusion == failure` with `jobs == []` and `name == path` = WORKFLOW-INVALID.
- **Single-sourced CI Python deps**: `requirements-ci.txt` (repo root) is the one list of CI test packages; every workflow pip step runs `pip install -r requirements-ci.txt`. `ci_workflow_lint.py` check 7 (`check_pip_install_single_source`) fails any pip step that re-lists a requirements-ci.txt package inline (fails closed when the file is missing). Packages outside the file, such as playwright, may stay inline.
- **CI modes (docs/CI-MODES.md)**: `common.py validate_ci_config()/load_aesop_config()` own the config `ci` block (mirrored code-for-code in `ci_config.js`; `tests/test_ci_config.py` runs both on the same fixtures); `ci_capability.py` is the report-only probe behind `aesop doctor` (Smart App Control / UMCI / WSL / Docker / gh / cloudflared / receipt tools -> mode table; `AESOP_CI_PROBE_FIXTURE` injects probes); `runner_install.py` shares its `runner_blocked()` predicate as preflight;
  - `init_project.py --ci-mode` renders `templates/ci/*.yml` (verify-receipt.yml is a PLACEHOLDER until the receipt lane lands -- the scaffold refuses, never emits it); rendered workflows must pass `ci_workflow_lint.py` + `ci_needs_skip_guard.py` (`tests/test_ci_templates.py`).
  - Doctor's pre-push check (`doctor.js` `checkPrePushHook`) resolves hooks via `git rev-parse --git-path hooks` (fallback `--git-common-dir`), worktree- and `core.hooksPath`-aware; FAILs with git's error when git cannot answer (`tests/cli-doctor-defects.test.mjs` DEFECT 7).
  - Doctor also checks each push-gate artifact (`PUSH_GATE_ARTIFACTS` in `doctor.js`: `tools/INDEX.md` and the `.pyflakes`/`.subprocess-guard`/`.portability`/`.stateapi` baselines); a missing one FAILs with its regenerate command (`tests/doctor-baseline-checks.test.mjs`).
  - Doctor layout (`detectLayout()` in `doctor.js`): an explicit `aesop.config.json` `"layout"` key (`init` is written by `init_project.py`), else inferred from the scaffold directories; the init layout reports the five-directory check as `n/a (init layout)` and every other check still runs, while the `~/.claude/skills` check runs only with `--global` (`tests/doctor-layout-mode.test.mjs`).
- **Node-suite HOME isolation (G8)**: `test_isolation_tripwire.py` is wired around every Node test invocation (`npm run test:node`/`npm test`, and the CI "Run Node.js tests" step), paired with `tests/helpers/isolated-env.mjs` (loaded via `--import`, redirects `HOME`/`USERPROFILE`/`AESOP_SKILLS_HOME`/`AESOP_HOME` to a throwaway temp dir for the whole process) as the structural fix; the tripwire is the independent behavioral proof, snapshotting `~/.claude/{skills,settings.json,memory,hooks}` + global git config before/after and failing closed on any drift.
  - GAP fixed 2026-10-06 (PR #831 shipped both files but wired neither into any Node test invocation, so every suite but one still ran against the real profile); `tests/isolated-home-tripwire.test.mjs` fails red under plain `node --test` (no `--import`) and green under the wired command, proving the wiring instead of just the fixture's existence.
  - **Cross-site drift guard (second GAP, 2026-10-06)**: PR #864 wired the first GAP's fix into TWO sites (ci.yml's ubuntu step, ci.yml's windows-shard raw invocation) but missed a THIRD, pre-existing site -- `main-full.yml`'s own raw `node --test ...` line -- which ran unisolated on every main-full run, staying accidentally green on windows-latest (USERPROFILE is an ambient OS var there) and genuinely RED on ubuntu-latest.
  - `node_harness_wiring_check.py --check` enumerates EVERY Node-suite invocation site across `.github/workflows/*.yml` + `package.json` (resolving `npm run test:node`/`npm test` through to package.json's own script) and fails closed if any site is missing `--import ./tests/helpers/isolated-env.mjs` or the tripwire wrapper -- catching the SHAPE of the gap (partial wiring across sites) so a fourth site drifts loudly instead of silently. Wired into `ci.yml` alongside the other workflow-scanning gates.
  - **Changed-path attribution (2026-10-15, two honest pushes blocked):** every changed profile or fleet-state path is classified before judging (`build_attributor`): `git-deploy` = a file inside a git-checkout `~/.claude` whose HEAD moved during the run (reflog entry inside the window) and which is now a clean tracked file (INFO, not a failure); `live-writer` = a `LIVE_WRITER_ALLOWLIST` file (the one allowlist in `tools/test_isolation_tripwire.py`) with a pidfile/heartbeat mtime inside the window (INFO); anything else fails, and the `VERDICT:` line lists every path with its class. Tests: `tests/test_test_isolation_tripwire.py` `TestGitDeployAndLiveWriterAttribution`.
  - **Compact-on-stop job files (2026-10-17 incident)**: `state/compact-on-stop-job-<pid>.json` (`COMPACT_ON_STOP_JOB_RE`) is a live-writer event (INFO, not a failure); no other fleet-state path matches. Tests: `TestCompactOnStopJobIsLiveWriter`.
- **Live-heartbeat tripwire (shell runner, 2026-10-14 incident)**: `run_shell_tests.sh` (`run_test` reports the file's real exit code, captured before the failed-list append that reset `$?` to 0) snapshots the REAL `~/conductor3/state/.watchdog-heartbeat` (override `AESOP_LIVE_HEARTBEAT`) before pinning HOME and FAILS the run if it changes to anything other than an in-window daemon epoch (placeholder `1234567890`, stale epoch, deletion). Verdict functions `live_hb_snapshot`/`live_hb_verdict` are proven by `tests/test-run-shell-tests-live-heartbeat.sh` on fixtures only. `ui/config.py` resolves heartbeat paths at import time to the real `~/conductor3` when it exists, so Python tests that touch `config.WATCHDOG_HEARTBEAT` must re-resolve under a fixture (`tests/test_wave13_ui_correctness.py`). Note: `npm run test:py` is NOT wrapped by `test_isolation_tripwire.py`, so this shell check is the only live-file net for Python-side writes until that wrap lands.
- **CI lint fail-closed (adv-enforcement F-07/F-08/F-09/F-10)**: `ci_gate_runability.py` and `ci_needs_skip_guard.py` read required-check names from `required-checks.json` (+ optional `--protection-file`), FAIL when a required name has no job in ci.yml, and check every script a gate step invokes (block scalars and multi-file steps included); an unreadable manifest exits 2.
