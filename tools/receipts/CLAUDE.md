# tools/receipts — the receipt gate (emit, verify, spool, flush)

Purpose: the receipt gate for pushes, covering emit, verify, spool and flush of signed run receipts.

- **Receipt conclusion exit codes (2026-10-15)**: `emit_receipt.py --fail-on-red` exits 3 when any part is red (after posting); `--pushed-red` (the `AESOP_PUSH_RED=1` override) stamps `pushed_red: true` before signing and exits 4 on red; exit 2 means could not produce. `exit_code_for()` is the single source; tests in `tests/test_emit_receipt.py::TestRedGateExitCodes`. The pre-push hook blocks on 3 and on any exit other than 0/4.
- **No server-side branch update (2026-10-15, receipts increment (a))**: no tool, script, hook, workflow or skill may call GitHub's branch-update endpoint or its CLI wrapper, because the merge head it creates is authored by GitHub and no box ran the gates on it. `merge_train.update_branch()` and `pr_sweep.behind_refusal()` refuse BEHIND PRs without a gh call. A lane merges `origin/main` locally, regenerates, and pushes. Guard: `tests/test_no_update_branch_guard.py` (repo-wide scan of tracked tools/, scripts/, hooks/, .github/, skills/). `verify_receipt.py` names this cause in its MISSING line when the head is a two-parent merge committed by `GitHub <noreply@github.com>` (`server_authored_merge()`, read from `git cat-file`; tests: `tests/test_verify_receipt_server_merge.py`). Every MISSING line also names the head sha, its commit author (`git log -1 --format=%an`) and a hint to push from a receipted worktree (`_missing_suffix()`; the hint is never printed on a VALID or INVALID verdict).
- **Receipt gate (measurement period, increment 2a spool-and-flush + isolation + durability)**: `emit_receipt.py --post` signs a local run with matrix parts running in a detached throwaway worktree (not the caller's tree) to prevent tests creating fixture repos from committing into the lane's branch; parts run with `scrub_child_env()` (GIT_DIR, GIT_WORK_TREE, etc. unset as defense in depth against git's hook environment; push/lane-control inputs AESOP_ALLOW_GENERATED, AESOP_STATE_ROOT, CONDUCTOR_ROOT and kin removed so a lane's push-time override cannot turn a test red; receipt signing material AESOP_RECEIPT_KEY and AESOP_RECEIPT_HMAC_SECRET is removed too, because a part runs the pushed head's test code and must not be able to forge a receipt (the parent signing call still reads them);
  - AESOP_CI_SHARD_TRIPWIRE_ARMED is removed too, because `ci_shard_runner` skips its isolation tripwire whenever it is set, so an inherited value would run the matrix with the tripwire disabled (test: `tests/test_emit_receipt.py::TestShardEnvScrubsTripwireArmed`); the receipt's `env.scrubbed` records the removed NAMES, never values); caller tree is verified untouched via tripwire. Ed25519 key resolved via `resolve_receipt_key_path()` — `$AESOP_RECEIPT_KEY` env var, then `~/.aesop/receipt_key.pem`, then `$AESOP_HOME/.aesop/receipt_key.pem`; pub `receipt_pubkey.pub`.
  - NEW scoped profile (default, `AESOP_RECEIPT_PROFILE=scoped`): runs fast pre-push gates always (`secret-scan`, `claudemd-sync-gate`, `gen-tool-index`, `verify-test-suite-count`, `encoding-lint`, `import-resolution-check`, `sibling-import-check`) PLUS only python shards owning files changed in the push (derived from `git diff --name-only <base>..<tip>` mapped through ci_shard_runner's shard assignment: round-robin, or greedy timing bin-packing when `.github/shard-timing.json` is non-empty, via the same `distribute_shards` / `distribute_shards_by_timing` functions CI calls, so the emitter cannot drift from CI); shards not in scope recorded as skipped with reason "not in scope: no changed file maps to this shard (profile=scoped)";
  - falls back to full if shard mapping cannot be derived, and also when the change set itself cannot be derived (merge-base or diff fails): it logs one `scope: cannot derive changed files` line and runs the full matrix (fail closed; an empty scope would pass with zero Python tests run). Tests: `tests/test_emit_receipt_secret_scrub_fallback.py`. Solves pre-push timeout issue: full matrix ~1250s (exceeds 900s hook timeout); scoped runs in minutes for docs-only or minimal changes. Full profile (`AESOP_RECEIPT_PROFILE=full`) available for explicit measurement. Profile recorded in signed payload (`profile: "scoped" | "full"`), backward-compatible (legacy receipts without it treated as "scoped"). When the commit doesn't exist on GitHub yet (pre-push hook timing), the commit-comment fallback gets 422 ("No commit found for SHA");
  - instead of raising, `post_receipt()` writes the signed envelope to a spool dir resolved via `resolve_spool_dir()` (in `receipt_common.py`; precedence: `$AESOP_RECEIPT_SPOOL` env, then `<git-common-dir>/aesop-receipt-spool` for worktree durability, then `~/.aesop/receipt-spool` fallback) and returns "spooled". This location survives worktree removal so lane cleanup cannot discard a pending receipt. **Failed-part logs**: a part that exits non-zero has the last 200 lines of its stdout and stderr kept in `state/receipts/parts/<head_sha>/<part>.log` (the envelope keeps only name/exit_code/test_count/duration_s) and `emit_receipt.py` prints that path; the tripwire excludes that directory because it is the emitter's own write, not a matrix mutation.
  - NEW `receipt_flush.py` (idempotent, exit 0 unless `--strict`) collects receipts from primary + legacy (`<repo>/state/receipts/spool`) fallback sources, checks each sha against GitHub (`gh api repos/.../commits/<sha>` 200), posts via `post_receipt()` if it exists, and deletes the file on success; flush runs with scrubbed env for isolation. Flush runs (fail-open) at START of `check_emit_receipt()` in pre-push hook (bounded, ~10s), in `pr_sweep.py` (for ITS OWN repo; the old `~/aesop` target was a stale non-git copy, so nothing was posted), and every watchdog cycle (`run_receipt_flush`). NEW `receipt_autoflush.py --spawn` (spawned by the hook after a "spooled" emit) forks a DETACHED poller: `gh api` every 15s for 600s, posts the spool for that sha as soon as it exists, logs to `<spool>/<sha>.flush.log`, never holds the push. `AESOP_RECEIPT_AUTOFLUSH=0` opts out;
  - `AESOP_GH_BIN` overrides the gh executable (test seam). Supports `--max-age-days` (default 7) to drop stale spools. `verify_receipt.py` recomputes tree hash + freshness; `verify-receipt.yml` non-required. Receipts include optional `schema_version=1` field for forward compatibility; legacy receipts without it still verify. `verify_receipt.py --fetch-for-head SHA --repo-slug OWNER/REPO` (backed by `fetch_receipt_for_head()`) is the Action's own lookup step, wrapped by `poll_receipt_for_head()` (bounded poll: default 300s window every 20s, `--fetch-window-s` 0..900, `--fetch-interval-s` >=1; stops as soon as the receipt appears, because the autoflush posts only after the push lands and a single lookup lost that race on PR #1035) — it NEVER raises;
  - any lookup failure (gh api error, malformed payload, this module absent on a stale PR tree) degrades to "MISSING receipt" and exits 1 (fail-closed, never a crash; a missing receipt fails the job) (2026-10-06 incident: #856/#857 showed FAILURE from an uncaught ModuleNotFoundError in the old inline fetch script). Ed25519 verification is a keyring: the committed `tools/receipt_pubkey.pub` plus every `tools/receipt_pubkeys/*.pub`, selected by `sig.key_id` (`receipt_common.keyring_paths()` / `verify_signature_keyring()`); tests in `tests/test_receipt_keyring.py`. Base-pinned trust: `verify-receipt.yml` checks out `base.sha` into `./base` and runs the BASE-tree receipt verifier with `--keyring` pointing at the BASE-tree `receipt_pubkeys` directory, so a PR head cannot supply its own verifier or keyring (rogue key verified); `--required ""` is refused unless `--allow-no-required-parts`.
  - See docs/archive/RECEIPT-GATE.md and its "Isolation mechanism" and "Spool-and-flush design" sections.
- `emit_receipt.py` zero-shard honesty: a scoped push whose parts all pass but select NO python shard posts check-run conclusion `neutral` (not `success`); any red part is still `failure`. `verify_receipt.py` accepts a zero-shard receipt only when the diff is docs-only (empty owning set requires no py shards); an unowned tools/ change still fails closed to all four shards. Tests: `tests/test_emit_receipt_scoped_profile.py::TestZeroShardConclusionIsNotSuccess`.
- **Receipt agreement measurement (increment 4 precondition)**: `receipt_agreement.py` measures local receipt vs hosted CI agreement for increment 4 gating. Fetches recent PRs via `gh pr list`, compares each head sha's local receipt parts (py-shard-0..3) with hosted check-run results (ci (0..3) jobs), and reports parts compared, agreements, disagreements (with sha + part + local vs hosted status), and agreement %. Supports `--json` output, `--limit N` (PRs sampled), `--require PCT` (fail if agreement < threshold). TDD with injectable fetchers (no network); exit 0 always unless `--require` specified. Tests verify agreement, disagreement, missing receipts, unknown parts, and hosted check-miss cases.
- **emit_receipt.py scoped shard selection fails closed (6615092dd3cd)**: a `tools/` change that no shard owns (e.g. `tools/receipt_common.py`) selects the FULL matrix, never zero shards (`_find_owning_shards` returns None only for an unowned `tools/*.py`; non-.py files under `tools/` such as docs own no shard and contribute nothing). Discovery is anchored at the worktree root (`git ls-files :(top)tests/test_*.py`; `--repo` resolves to `rev-parse --show-toplevel`), not the cwd. Registry shard argv passes `--timing-file .github/shard-timing.json` as ci.yml does, so the selection map and the executed buckets share one assignment. Out-of-scope shards are recorded in `skipped` with reason "not in scope". Tests: `tests/test_emit_receipt_secret_scrub_fallback.py::TestScopedFallbackFailsClosed`.
  - Both fallbacks (underivable shard map, unowned `tools/` change) run the injected `registry` (`list(registry)`), never `DEFAULT_MATRIX`; tests: `tests/test_emit_receipt_scoped_profile.py::TestScopedFallbackUsesInjectedRegistry`. **emit_receipt.py trunk and non-GitHub remote (fix/emit-receipt-bootstrap-main-ref)**: `resolve_trunk()` mirrors the pre-push hook's `gate_trunk_ref` (explicit `--main-ref` if it resolves, else origin/HEAD target, origin/main, origin/master, else `HEAD` for a fresh-remote bootstrap); `base_sha` is the merge-base with that ref and the receipt records it as additive `trunk_ref`. A configured non-github.com origin (`non_github_remote()` reads the raw `remote.origin.url`, not `remote get-url`, which applies the test harness's insteadOf rewrites) skips the check-run POST, prints one WARN and records `posted: {skipped, remote}` before signing;
  - no origin and any github.com error still go to the POST and fail closed. Tests: `tests/test_emit_receipt.py::TestTrunkResolution`, `::TestNonGithubRemotePost`.
- **emit_receipt.py per-part timeout (fix/emit-receipt-part-timeout)**: `run_part()` bounds each matrix part with `AESOP_RECEIPT_PART_TIMEOUT` seconds (default 600, below the hook's outer 900s). On expiry the whole process tree is killed (`taskkill /T /F` on Windows, `killpg` on POSIX), the part is recorded with exit 124 and its log notes "timed out after Ns", so the receipt is red and the push blocks. Invalid, zero, negative or non-finite values use the default and warn on stderr; the bound is never disabled. Tests: `tests/test_emit_receipt.py::TestPartTimeout`.
- **verify_receipt.py default --main-ref (trunk-resolved)**: the default `--main-ref` resolves through `emit_receipt.resolve_trunk(repo)` (origin/HEAD target, origin/main, origin/master, etc.) instead of the hardcoded `origin/main`; an explicit `--main-ref` is used verbatim and fails closed (exit 2) when unresolvable. **Scoped profile (fix/receipt-scoped-required-parts)**: for a scoped receipt the required shards are recomputed from the receipt's changed files (`git diff base..head`, mapped by `emit_receipt._find_owning_shards`), and fail closed to all four shards only when the owning set is None (underivable map or change set, or an unowned tools/ change); an EMPTY owning set (docs-only diff) requires no py shards, matching the emitter's 7-part scoped receipt (fix/verify-receipt-docs-only-required). A full-profile receipt keeps the caller's `--required`. Tests: `tests/test_verify_receipt.py::TestScopedRequiredShards`.
- **emit_provenance_receipt.py (v0.11.0)**: signs `{schema, kind:"provenance", repo, version, subject:{path, sha256}}` as an Ed25519 envelope `{receipt, sig}` (key at `$AESOP_RECEIPT_KEY`); `--verify ENVELOPE --subject FILE` recomputes the sha256 (CRLF folded to LF) and checks the signature against `tools/receipt_pubkeys/*.pub`. It does not evaluate run receipts: `verify_receipt.py` reports CANNOT EVALUATE on this envelope. Used for `docs/PROVENANCE.receipt.json`.
