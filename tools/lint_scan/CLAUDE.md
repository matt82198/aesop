# tools/lint_scan — lints, scans and the incident classifier
Scripts in tools/ that classify incidents, scan for secrets, lint the tree and detect lint evasion.

## Incident reports
- **incident_report.py output is portable (2026-10-14, ci (0) portability ratchet)**: `IncidentMarkdown.generate_table()` redacts whole-word private-machine tokens to `[redacted]` (`redact_private_tokens`), because #946's body classification pulls historical commit subjects into the table and `docs/INCIDENTS.md` is shipped surface. `write_table()` writes LF on every host (text-mode writes CRLF on Windows). Tests: `tests/test_incident_report.py` `TestIncidentPortabilityAndEol`. The portability ratchet (`portability_check.py`) FAIL line names CI-A14 in docs/CI-CATALOG.md (case a: a new literal home path, case b: stale baseline). `portability_check.py` now matches home paths case-insensitively and JSON-escaped, and has a `--tracked` mode that reports posix keys.
- **chaos_harness.py reports sandbox.name**: the harness writes `sandbox.name` instead of the full sandbox path, so the report carries no real machine path.
- **incident_report.py record parsing is deterministic (2026-10-14)**: `IncidentParser.find_all_incidents()` reads `git log` with US (`%x1f`) field and RS (`%x1e`) record separators, so multi-line bodies and `|` characters cannot split a record. An unparseable commit date falls back to a fixed epoch, never `datetime.now()`: a wall-clock fallback made the sort key change on every run (test: `tests/test_incident_report.py` `test_deterministic_ordering`, `test_multiline_body_keeps_real_dates_and_stable_order`).
- **incident_report.py classification is fail-closed (2026-10-14)**: an `Incident-Class:` commit trailer (13 classes incl. `environment-shape`; `test-isolation` is a documented alias of `test-pollution`, normalized on read; optional `Incident-Category: <A..E name>`) is authoritative; an unknown class or category makes `--check`/`--regenerate` exit non-zero naming the commit and writes nothing; commits without the trailer classify from the subject only and are marked `(inferred)`; body keywords and `Merge` subjects never classify; only the final blank-line-separated body paragraph is scanned for trailers, so prose wrapping onto an `Incident-Class:` line cannot fail the gate; `--output` accepts absolute paths and print mode survives a cp1252 console.
  - Record parsing stays deterministic: US (`%x1f`) and RS (`%x1e`) separators, git commit dates, no wall-clock fallback (tests: `tests/test_incident_report.py`, incl. `test_multiline_body_keeps_real_dates_and_stable_order`).
  - Scope is HEAD's history (`git log HEAD`) by default, so an unrelated local or remote branch cannot fail the gate; `--all` is forensic only. CI job `incident-report-gate` (ci.yml) runs `--check` on every PR; it is not a required context.

## Secret scan
- **secret_scan generic_credential_assignment skips slash-delimited regex literals (f-332fcec2)**: complements the regex-syntax exclusion from #1224 (which covers values with `\s`/`(?`/`[^` plus a quantifier); this covers a `/body/` value with no regex syntax. The unquoted value branch carries a `(?!/[^\s/]+/[gimsuy]*(?=\s|$|[;,]))` lookahead, so a COMPLETE slash-delimited value (`SUPPRESSED_CRED = /body/gi`) is code, not a credential; text after the closing slash other than flags (`/pw/tail`) keeps it a credential (audit 2026-10-22 #3). Unwrapped credentials of the same shape and unclosed slash-prefixed values stay flagged. Rule is not pragma-softenable and no skip token was added. Tests: `tests/test_secret_scan_regex_literal.py`.
- `secret_scan.py --staged` — pre-push gate (exit 0=clean/1=findings/2=error; `# secretscan: allow-pattern-docs` pragma softens only `env_access` (never `generic_secret_assignment` or `generic_credential_assignment`: the pragma is self-asserted, so it cannot launder a real credential; doc examples use a placeholder value that each rule's own placeholder check excuses)
  - `generic_credential_assignment` flags `KEY_NAME=value`/`KEY: value`/`KEY = "value"` outside .env files, with the name class PASSWORD|PASSWD|PWD|SECRET|TOKEN|CREDENTIAL|CRED|BEARER|API_KEY|PRIVATE_KEY|ACCESS_KEY (plural CREDENTIALS deliberately unmatched: `credentials: 'same-origin'` is a fetch option; unquoted values may contain dots, so `DB_PASSWORD=<value.with.dot>` is fatal, while dotted attribute chains such as `self.serve.SESSION_TOKEN` and `...` doc ellipses stay CLEAN; a value that is a regex literal, i.e. a regex class escape or group/negated-class syntax plus a quantifier, is excused the same way the connection_string regex-shape exclusion excuses its rule-table literals, and a real-looking value with no regex syntax stays fatal)
  - NUL/UTF-16 files are decoded and scanned in full; ANSI escapes do not make text binary, and a binary blob still gets every rule over its printable runs; staged/ranged blobs are never skipped by path class (node_modules, __pycache__, .pyc/.pyo are skipped only in the working-tree walk); a connection_string placeholder check covers the password only; placeholder words match whole tokens, and a trailing comment is stripped before the code-identifier check; files over 16 MiB fail closed
  - a path argument (or `--from-stdin` entry) that is neither a file nor a directory exits 2 with a FATAL line naming it, never a CLEAN 0-files result; FATAL-rule placeholder excuses now need a placeholder-only body after at most two short prefixes, and staged/range listings use -z so non-ASCII paths are read; `generic_secret_assignment` exempts an unquoted complete subscript of a bare name (`parts[0]`, `token[2:]`); tests: `tests/test_secret_scan_blindspots.py`, `tests/test_secret_scan_failclosed.py`)
- `secret_scan.py` `scan_content` (history/prepublish path, scan-content-dsn): connection_string matches route through the same password-only placeholder check as `scan_blob`/`scan_file`, so a real DSN ending in `/test` is a finding; tests: `tests/test_secret_scan_content_dsn.py`. The connection_string host exclusion covers only local hosts (localhost, 127.x, `.local`, `.localdomain`), so an `example.*` or `test.*` host no longer excuses a real password: such a DSN is clean only when its password is a placeholder (tests: `tests/test_secret_scan_fail_closed_audit.py::TestExampleHostNoLongerExcusesPassword`).
- **secret_scan has NO clean-verdict cache (removed, audit 2026-10-22 #2)**: the #1246 cache let a hand-written `clean.json` under `$AESOP_STATE_ROOT` or the temp dir bless a secret file, so every scan is a full scan. `--no-cache` remains an accepted no-op for old callers. Patterns are still compiled once. Tests: `tests/test_secret_scan_clean_cache.py`, `tests/test_secret_scan_fail_closed_audit.py`.
- **secret_scan audit 2026-10-22 fail-closed fixes** (tests: `tests/test_secret_scan_fail_closed_audit.py`): (1) `--range` scans every blob introduced by any commit in `git rev-list <range>` by object id (`git diff-tree --stdin -r -m --root`, then `git cat-file blob <id>`), so a secret added then removed in one push is found; a tree base (the empty-tree sentinel) means every commit reachable from the tip;
  - (3) the unquoted slash exclusion needs a closing slash followed only by flags and end-of-value (`NAME=/pw/tail` is a credential); (4) the regex-shape exclusion also requires no credential-looking token (16+ alnum, or 8+ mixing digits or case) in the literal text left after the regex escapes; (5) `_is_whole_placeholder`: a placeholder word excuses a value only when every other hyphen/underscore/dot segment is plain (digits or one-case letters), so `Zx9-test-Qm2L` is a finding while `changeme-prod-1234` is not;
  - (6) `dsn_query_password` rule flags values of the password, pwd and passwd query-string keys, including inside quoted DSNs; (8) a path or `--from-stdin` scan that inspects zero files exits 2 `NOTHING SCANNED` (skipped vendored and compiled files are not counted as scanned); (9) `--staged` with an empty index exits 1 `EMPTY-INDEX` unless `--allow-empty`, which gates and hooks never pass (`prepublish_scan.py` passes it; `eod_sweep.py --fix-push` now scans `@{upstream}..HEAD`); (10) `GIT_DIR`/`GIT_WORK_TREE`/`GIT_COMMON_DIR`/`GIT_PREFIX` are scrubbed from every git call (repo comes from `--repo`/cwd).

## Lints
- **Subprocess encoding (G10)**: every `subprocess.run`/`Popen` decoding output passes explicit `encoding='utf-8'`; the platform default is cp1252 on Windows and corrupts non-ASCII output. `encoding_lint.py` scans the WHOLE repo, so one violation anywhere blocks every Python-touching push. Same trap hits argparse `--help` text: a Unicode arrow/dash in a `help=`/`description=` string crashes `print_help()` on a stock cp1252 console
  - (the encoding rules check only `subprocess`/`open`; the ASCII rule `encoding_lint.ascii_findings` now gates every `tools/*.py` source file against the shrink-only ratchet `tools/encoding-ascii-baseline.json`, which accepts two shapes: the list `{"files": [str, ...]}` exempts a file whole, and the count `{"files": {path: int}}` caps a file's non-ASCII characters, where a rise is blocked, a fall passes, and an absent file allows zero)
  - keep all argparse-printed text plain ASCII (`->`, `-`); fixed 2026-10-05 in `auto_merge.py` + 7 other tools' `description=` strings.
- **ASCII ratchet scope (2026-10-15)**: `encoding_lint.ascii_findings` now covers `tools/*.py` AND `.github/workflows/*.yml` (non-recursive). A non-ASCII byte in a workflow breaks cp1252 yaml loads (regen-on-main.yml U+1F422 at byte offset 5438 was the trigger). Use GitHub shortcodes such as `:turtle:` in workflow strings, not emoji. The five workflows that held non-ASCII (ci, crossos-drift, main-full, publish, reproduce; 22 characters, all YAML comments or echo display text) were made ASCII (`--` for em dash, `->` for arrow, `OK` for check mark) rather than grandfathered, so the workflow scope carries zero baseline entries.
- **Encoding-lint scan integrity (bcddd626dc26)**: junk-dir skipping (cache dirs, `.git`, `node_modules`, `dist`) matches only path parts BELOW `--root`, so a checkout under a `dist` ancestor is scanned. A nonexistent `--root` exits 2; a scan that collects zero Python files exits 2 (`no Python files scanned`) and never prints `[OK]`. Tests: `tests/test_encoding_lint.py::ScanRootHardeningTest`.
- **In-process HTTP timeout lint (escape main-full-windows-shard2-ui-acceptance-timeout, 2026-10-17; v2 guard/inprocess-http-timeout-lint-v2)**: `inprocess_http_timeout_lint.py` AST-scans `tests/**/*.py`; a `HTTPConnection`/`HTTPSConnection`/`urlopen`/`requests.<method>` call is in scope when its host is loopback, non-literal, or the module starts an in-process server (`serve_forever` / `QuietThreadingHTTPServer`, same module or not); its timeout must be a numeric literal or a module-level name bound only to numerics, and a constant under 30 s is a hit (exit 1), while any other non-literal timeout is banned.
  - A `# timing-ok: <reason>` on the call line (non-empty reason) is an escape. `.inprocess-timeout-baseline.json` (`_generated` date + `escapes` total + per-file hit ceilings) ratchets both and EXPIRES 30 days after `_generated` (`--max-age-days`); re-measure only with `python tools/inprocess_http_timeout_lint.py --emit-baseline > .inprocess-timeout-baseline.json`.
  - Wired in ci.yml shard 0; pre-push `check_inprocess_http_timeout()` reads the TRUNK copy and fails CLOSED when the tool is missing. Repaired: `tests/test_ui_acceptance_criteria.py` client timeout 5 s -> 30 s. Tests: `tests/test_inprocess_http_timeout_lint.py`.
- **Dead-baseline liveness (GUARDRAIL #3)**: `baseline_liveness_check.py` finds each `.*-baseline.json` ratchet baseline's consumer (hardcoded usage in `tools/*.py` that also DECLARES `--baseline` via `add_argument("--baseline")` or an argv `== "--baseline"` parse, so a string table quoting `--baseline` is not a consumer; a writer/seed table that only quotes the filename is skipped with an INFO line, or `--baseline` wiring in `.github/workflows/*.yml`/`hooks/*.sh`) and re-runs that consumer's own `--baseline FILE --json` check to surface entries it no longer finds (stale allowance hiding a new violation); a baseline with no consumer is DEAD, fail-closed. `--prune` drops exactly the stale entries (shrinks counts, never raises them). CLI `[--root DIR] [--prune] [--json]`, exit 0=clean/1=dead or stale/2=error, stdlib-only; wired into `ci.yml`.
- **Pyflakes ratchet gate (Guardrail G15, 2026-10-06)**: `pyflakes_gate.py` wraps `python -m pyflakes` over `tools/ bin/ ui/ state_store/ driver/ monitor/ daemons/ tests/ bench/`, keying findings as `file@MessageClassName` (e.g. `UnusedImport`, `UnusedVariable`) against the committed `.pyflakes-baseline.json` (same bidirectional exact-match ratchet as `.portability-baseline.json`); fails closed on a NEW finding, fails closed on a STALE baseline entry (a fix must regenerate the baseline in the same PR), and fails closed (exit 2) if the dev-only pyflakes package is not installed. `--update-baseline` is review-only; CI never passes it. Tests: `TestPyflakesIncrementalParity` in `tests/test_pyflakes_gate.py`.
  - Closes a ~900-finding unused-import/unused-variable backlog that accumulated because nothing had ever run pyflakes in CI; the remaining baselined findings are deliberately-frozen `bench/seam_tasks/` ground-truth fixtures, guarded re-export/import-probe patterns (`# noqa: F401`/`# noqa: F841` with a reason), and out-of-scope categories (e.g. `FStringMissingPlaceholders`). CLI `[--check] [--json] [--paths DIR...] [--root DIR] [--baseline FILE] [--update-baseline] [--no-cache] [--cache-dir DIR]`, exit 0=clean/baselined, 1=new-or-stale findings, 2=error; wired into `ci.yml` shard 0.
  - Per-file result cache: pyflakes analyses one file at a time, so each file's messages are cached under `$AESOP_STATE_ROOT/cache/pyflakes` (else the temp dir), keyed by repo-relative path plus sha256 of the bytes and one file per `--root`; the verdict equals a full scan. `--no-cache` forces a full scan; the JSON `scan` block and the `pyflakes_gate: scan ...` line report `incremental` or `full` with the fallback reason (cold cache, cache unreadable, cache version mismatch, baseline missing, `--update-baseline`, `--no-cache`).
- **Dispatch policy linter (G12)**: `dispatch_lint.py --check` enforces merge automation and lane protocol rules in agent dispatch prompts — detects forbidden patterns (`gh pr merge`, `--admin`/`--auto`/`--no-verify`/`--force`, `git stash`, credential hunting, and assignment of the gate-escape `AESOP_*` variables listed in `AESOP_ESCAPE_VARIABLES` — same severity as `--no-verify`; `BUILDLOG.md` and `STATE.md` are exempt from that one rule) and lane-side CI polling (`ci_merge_wait`, `gh run watch`, `merge_train.py`, sleep-wrapped `gh pr checks`). Lane terminal action: push → open PR → `gh pr edit <n> --add-label merge-queue` → exit (merge-queue advancer owns CI-wait).
  - Excludes test files and `tests/`/`state/` path components (exact names, relative to the scan root); `#` is a comment only at line start or as a spaced trailing comment (`PR #845` is scanned); a `//` inside a URL scheme (`https://`, `file:///`) is not a comment marker, so a forbidden command after a URL on the same line is still flagged (tracker 1f024dc61697, tests `TestUrlDoubleSlashMasking` in `tests/test_dispatch_lint.py`); inline backtick spans and ``` fences are scanned, not exempt; markers (`# dispatch-ok`, `// dispatch-ok`, `<!-- dispatch-ok -->`) suppress.

CLI `[--check] [--fix] [--json] [PATH]`, exit 0=clean/1=violations/2=error, stdlib-only; wired into pre-push gates as a security check. Output is written as UTF-8 with `errors=replace`, so a cp1252 console shows the findings instead of crashing with UnicodeEncodeError; exit codes are unchanged.
- **StateAPI lint (F-01)**: `stateapi_lint.py` now scans `driver/` too (SCAN_DIRS); in driver/ a raw write whose target is tracker.json / `tracker_path` (os.replace/rename/move, write_text, open-w) fails closed via an AST rule that runs even when the file imports the WriteAPI facade. ## Evasion checks
- **Lint evasion (G11)**: `verify_no_lint_evasion.py` flags compile-time string construction that hides another gate's trigger token — adjacent-literal `+` chains, all-constant `str.join`, all-constant f-strings (Python via `ast`; `.js/.mjs/.cjs` via regex). Fires only when the RECONSTRUCTED value matches a gate token (word-boundary anchored) AND no single fragment contains that whole token, so for a protected `alpha.json` the form `prefix + 'alpha' + '.json'` is evasion while `prefix + 'alpha.json'` is not (the owning gate still sees the latter).
  - Reports file:line + reconstructed value + matched token; CLI `[--root DIR] [--paths P ...] [--json] [--check]`, exit 0=clean/1=findings/2=error, stdlib-only. Tokens are DERIVED by AST-parsing the `*_TO_PROTECT` tables in `stateapi_lint.py` — never imported and never re-spelled as literals here, since spelling them would make the detector itself a violation of the gate it protects — plus built-in ratchet-baseline filenames.
  - Sanctioned exemptions, deliberate and not to be "fixed": runtime-assembled dummy credentials (splitting those is a REQUIRED invariant, so credential-placeholder-shaped values are skipped), `tests/**/fixtures/` trees, and `# lint-evasion-ok` / `// lint-evasion-ok` on any line of the construction.
  - NOT yet wired into CI, so this entry deliberately does not claim wired-gate status (see the module docstring for that labelling rule): the first real-tree run found a live escape (`health_checks.py` splits two heartbeat filenames, commit 16b3f8e3, after which the stateapi baseline was ratcheted down 39->37); remediation needs facade routing plus a baseline change, so until then the tool exits 1 on the tree and `tests/test_verify_no_lint_evasion.py` pins the known-escape set as a bidirectional ratchet. Wire into `ci.yml` only once that set is empty.
